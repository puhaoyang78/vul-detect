# PrimeVul 函数检测：MIL 诊断与条件 BCE 实验

本轮未获得可采纳的新稳定提升，默认方法保持 Context + Diff。已完成历史权重和数据诊断、冻结干预、固定线性探针、两组匹配小实验、条件 BCE 完整训练及原方案新种子复现。官方 paired Train 为 4,354 对，Valid 为 562 对。全部新计算及方法选择使用 Train/Valid，Test 不参与。

统一使用本地 UniXcoder、首 510 个源码 Token 加两个特殊 Token、Batch8、FP32 eager、LOSVERAdamW、Seed123456、16 Epoch、固定 `probability > 0.5`。编码器沿用预训练配置中的 0.1 Dropout；配置中的 `dropout_probability=0` 是额外行头设置。完整训练每组 17,424 步，按完整 Valid P-C 四位小数选模，同分保留最早轮次。历史权重保留。

| 同预算全局均值，历史对照 | 123456 | 13 | 16.37% | 0.5726 | 0.1141 | 0.5699 | 0.5872 | 0.4733 |

Context + Diff 相对 LOSVER 新增正确配对 62 对、丢失 42 对，净增 20 对，即 3.56 个百分点。对同一 Valid 修复对进行 3,000 次固定种子重采样，P-C 差值的 95% 区间为 [0.00, 7.12] 个百分点，AUC 差值为 [0.0024, 0.0489]，MCC 差值为 [0.0103, 0.1014]。这是给定已选权重后的样本不确定性，不能代替训练种子稳定性，也不校正历史多次 Valid 选模的影响。

P-C 还需结合方向错误判断：若给不同可见输入独立分配公平硬币预测、相同输入共享预测，则该 Valid 的解析期望 P-C 和 P-R 均为 17.70%，AUC 为 0.5、MCC 为 0。这是无信息的解析参照，不是训练实测结果。Context + Diff 的 P-R 只有 3.74%，并有更高 AUC/MCC，体现了部分方向信号；不能只靠降低相似函数预测的相关性来宣称检测改善。

已确认的瓶颈如下。

- **可观测性与标签冲突。** 512 Token 下 Train 有 1,254/4,354 对、Valid 有 164/562 对输入相同，单函数确定性推理无法区分这些配对。按实际 Token、Mask、物理行及行内 Token 对应关系建立严格等价组，Train 有 2,531/8,708 个函数处于标签冲突组，经验 BCE 下界约为 0.2011。这是输入预算造成的不可辨识性，不能据此判定原始标签错误。所有成员和官方评价标签保留。
- **表面的长度效应主要来自截断。** Context + Diff 在截断函数对上的 P-C 为 13.08%，未截断为 25.23%；只看输入确有差异的配对后，两者为 45/180=25.00% 与 55/218=25.23%。纯新增修复整体 P-C 为 37/163=22.70%，可见差异子集为 37/123=30.08%，高于替换修复可见子集的 63/272=23.16%。旧侧没有 Diff 正标签并非当前最差的分类子集。
- **LOSVER 的定位泛化差距。** 同一定位器在 Train 的修改行 F1 为 88.70%，Valid 为 28.05%；Valid 精确率仅 24.96%。其 `softmax(token_weights)` 把标记值 5 与 1 变成约 `exp(4)=54.60` 倍的相对 Token 权重。冻结检测器、直接去掉预测掩码后，P-C 从 14.23% 降至 9.07%，AUC 从 0.5637 降至 0.5560，FPR 从 42.17% 升至 63.17%。掩码有泛化问题，但删除掩码也破坏检测器已学习的读出关系。正式推理逐项复现原预测，最大概率差为 0。
- **注意力和类别方向的对应关系未充分泛化。** 对共享线性分类器，注意力相对 Token 均值的 logit 变化等于 `Cov_n(r_i,z_i)/E_n(r_i)`。Train 上漏洞侧平均变化为 +0.751，修复侧为 -3.907；Valid 上变成 -0.938 与 -1.455。模型在 Train 学到的类别分离作用明显减弱。行投影只是函数分类器的代数分解，不是经过校准的行漏洞概率。
- **权重范围也限制了可修正性。** 固定行表示和分类器，逐函数允许独立选择最有利的 1～5 倍权重后，Valid 的 483 个函数错误仍有 309 个无法纠正；可见差异子集为 217/319 个。任意凸加权对应的数量分别为 101 与 84。完整 Valid 的标签知情 P-C 上界为 188/562，取消倍率约束后为 316/562。这些是松弛后的容量上界，不能当作可部署方法的性能。

在 319 个可见差异子集的函数错误中，84 个在任意凸权重下均无法纠正；133 个只有放宽 1～5 倍约束后才存在可纠正权重；另外 102 个在该范围内存在可纠正权重。范围极值通过排序后枚举阈值计算，并以小例子全部 `2^L` 个顶点穷举核对。Valid 极值距离零最近约 0.000336，分类边界的舍入不会改变上述计数。

固定 C=1、L-BFGS，仅在 Train 重拟合冻结表示上的线性分类器：最终层注意力表示的 BCE 探针 Valid P-C 为 16.37%、AUC 0.5790；加入固定权重 1 的函数对排序损失后为 15.84%、0.5808。相同探针设置下，第 4、8 层均未超过原模型，最佳 P-C 分别为 11.39%、12.99%。因此未据此新增中间层聚合或排序模块；这些结果也不能排除其他表示学习方法。

实例见 `cases.json`。TensorFlow 配对 `valid:18` 的新增保护检查在修复侧注意力前三行内，但修复侧所有行投影仍为正，最小值 0.436，任意凸聚合都无法把它判为负。Chrome 配对 `valid:2` 的修改行已经给出负投影并位居注意力首位，但 1～5 倍约束下修复侧最低函数 logit 仍为 3.800。该例安全机理保留 Unknown，模型代数事实单独记录。hhvm `valid:11` 的修改区域完全在当前可见范围外。Unknown 不改变官方函数标签和评价成员。

历史失败也呈现类似的代理目标问题。RCCL 使相同内容行在 Valid 的原始表示余弦相似度从匹配基线的 0.8529 降至 0.7638，但完整 Valid P-C 从 17.08% 降至 16.73%，随机 RCCL 为 17.44%；投影后的相似度 Train 为 -0.1668，Valid 为 0.6184。插入位置监督在可映射 Valid 子集上的 Top-3 命中为 38.52%，高于随机的 15.57%，但函数 P-C 为 15.66%。辅助任务确实可以学习，却未必改善函数类别及修复方向判断。

针对性调研使用原论文和官方实现：[ACMIL，ECCV 2024](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/06954.pdf) 与 [ASMIL，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/dea9b4b6f55ae611c54065d6fc750755-Abstract-Conference.html) 讨论注意力集中和不稳定；[MIL 实例可学习性，NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/1468ecc3d7e9dc2fbf336eed9bb292e0-Abstract-Conference.html) 提醒区分包分类与实例语义；[PrimeVul 官方对比学习代码](https://github.com/DLVulDet/PrimeVul/blob/main/os_expr/model.py) 和 [RankNet](https://www.microsoft.com/en-us/research/publication/learning-to-rank-using-gradient-descent/) 支持本轮对“表示距离/排序”和函数分类分开检验。没有直接复制这些方法的完整模块组合。

首先检验的训练改动是**条件 BCE**。对实际模型输入完全相同的 Train 组，令 `q_x = mean(y | x)`，使用 `BCE(logit(x), q_x) + 0.1*Diff区域损失`。所有函数仍参与训练，原始硬标签及 Diff 不变。BCE 对目标标签线性，因此确定性输出下经验目标完全相同；随机 Dropout 下仍有相同的期望目标，但移除了不可观测标签与随机视图的偶然对应。没有增加可训练参数、编码次数、损失超参数或推理输入。这也不是对全部样本统一设定一个平滑系数；[To Smooth or Not，ICML 2022](https://proceedings.mlr.press/v162/wei22b.html) 所讨论的风险使本轮没有采用统一标签平滑。

先用原入口运行匹配的 2,048 个 Train 函数、完整 Valid、16 Epoch、4,096 步。两组初始化流程、训练/验证成员、参数量及最终 CPU/CUDA RNG 状态一致；新方法仅改变训练 BCE 目标。

小实验通过预先记录的完整训练扩展条件，但伴随修复侧 FPR 升高 7.83 个百分点，不能据此认定分类已改善。随后完成全部 8,708 个 Train 函数的 16 Epoch。相对匹配的原 Context + Diff，条件 BCE 的 P-C 下降 1.07 个百分点，AUC 下降 0.00569，MCC 下降 0.01852。Train P-C 从 63.41% 增至 64.75%，但 Valid 下降；改善训练内拟合未转化为泛化收益。两组完整实验的成员、配置、参数量和末态 CPU/活动 CUDA RNG 均核对一致。该方向未通过预设扩展标准，没有追加种子或调整参数。

原 Context + Diff 的两个固定种子 P-C 为 17.79%、17.62%，均值 17.70%，样本标准差 0.13 个百分点。这只是同一开发 Valid 上的两次训练复现。LOSVER 仍只有一套固定的定位器/检测器权重，不能据此宣称已经验证其完整流程的多种子差异。失败候选只有一个完整训练种子，不将其描述为已经完成多种子验证。

日志累计训练循环耗时：条件 BCE 完整训练 50.20 分钟，原 Context + Diff 新种子 50.29 分钟；两组小实验分别 12.26、12.35 分钟。统计不含初始 Tokenization 和离线诊断，不作为严格的运行速度比较。正常训练、推理的编码次数和输入预算均未增加。

另一个预先记录的冻结检验是移除注意力倍率的加性下界：将 `n_i*(1+4*sigmoid(s_i))` 改为 `n_i*sigmoid(s_i)` 后归一化，固定原表示、分类器与 checkpoint，仍只输入单函数。使用精确分数导出和稳定的 `log(n_i)+logsigmoid(s_i)` 计算。结果 P-C 从 17.79% 变为 17.62%，AUC/MCC 均下降，未通过扩展标准。权重范围存在容量限制，但当前冻结分数直接去下界没有兑现这部分空间；没有搜索其他倍率、温度，也没有将它与条件 BCE 叠加或接入正式默认推理。

测试及 GPU smoke 记录见 `tests.json`、`gpu-smoke.json`；精确分数、物理行映射、容量界和逐样本结果可复查。94 项不同的相关单元测试通过，原权重上的真实 RTX 4090 smoke 通过，覆盖梯度、更新、RNG、恢复和推理不使用 Diff/训练目标。

完整条件 BCE 权重另做的严格概率一致性检查没有通过：完整 Valid 中 28/1,124 个函数的 Batch8/单函数概率差超过原定 2e-6，最大为 5.90e-6。输入完全相同，所检查的重复批量执行与移除 Diff 元数据差异均为 0，差异在编码器输出中已经出现。完整 Valid 的类别差异为 0，P-C、AUC、MCC、F1、Recall、FPR 完全相同；AUPRC 存在约 3.18e-7 的差异，因此没有将全部指标一致性标为通过。该精度项保留失败记录，诊断入口保存全部统计后仍以非零状态退出，没有放宽容差或改动默认推理。它不改变本轮候选方法的负面结论。张量缓存与权重仅保留本地。

复现命令及固定筛选规则记录在 `experiment.json`。模型与训练正式实现为 `vulnmechanism/model.py`、`training.py`、`cli.py`；`--marginalize-inputs` 默认关闭，`--paired-seed` 仅改变已记录的训练种子。诊断入口为 `python -m vulnmechanism.mil_diagnosis`，复用正式数据、物理行聚合和 forward，不复制模型训练框架。

本轮没有把任何新尝试选为默认方法。可观测性、定位器的 Train/Valid 差距、固定表示下的权重容量以及类别方向泛化不足都有实际证据；现有结果不支持把条件 BCE 或直接去下界作为论文主要方法贡献，也不证明尚未测试的其他训练方式一定无效。
