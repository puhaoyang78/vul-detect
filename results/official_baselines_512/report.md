## 上游版本与配置

- linevul: [https://github.com/awsm-research/LineVul.git](https://github.com/awsm-research/LineVul), commit `9401ec6e60b762a9308645961268203244bee048`; 10 Epoch最大预算，Batch16，Token512，lr=2e-05。
- svuld: [https://github.com/jacknichao/SVulD.git](https://github.com/jacknichao/SVulD), commit `6ebf229e92d030f68752cd2d361f56ff97dffcbd`; 20 Epoch最大预算，Batch32，Token400，lr=2e-05。
- regvd: [https://github.com/daiquocnguyen/GNN-ReGVD.git](https://github.com/daiquocnguyen/GNN-ReGVD), commit `b5e6657b003ada704b7c75e4bd237c1eee1d8138`; 100 Epoch最大预算，Batch128，Token400，lr=0.0005。
- losver: [作者源码](https://github.com/waroad/losver), 历史元数据源版本 `a158905cb45b4400f481f18eeb1cb4473ccfccdc`；沿用已确认的source_offsets/512输入和线性函数分类头。这些已有实现修正与历史Seed123456一致，本轮未改动；不称为未经适配的论文数值复现。

必要修改见vulnmechanism/upstream/*.patch：数据/固定评价/已有断点续训接口，可选解释和日志依赖延后加载，SciPy及NumPy符号更新，ReGVD旧Transformers AdamW使用仓库同一更新规则。
核心依赖未降级。正式训练由tmux管理，原作者前向、反向和优化步顺序保留。

环境：Python 3.11.14，CUDA 12.8；torch 2.9.1，transformers 4.57.3，numpy 2.4.0，scipy 1.16.3，pandas 2.3.3，scikit-learn 1.8.0。

## 复现与验证

```bash
python -m vulnmechanism.cli official-baselines prepare
python -m vulnmechanism.cli official-baselines smoke --method linevul --seed 42 --device cuda:0
python -m vulnmechanism.cli official-baselines run --method linevul --seed 42 --device cuda:0 --resume
python -m vulnmechanism.cli official-baselines report
```

method分别选择linevul、svuld、regvd，seed分别选择42、1234、123456。每个作者训练循环使用相同的正式接口，组合级文件锁防止多个tmux队列重复训练；恢复复用原项目模型/优化器/调度器/RNG原子保存与日志截断。
测试包括实际数据成员/标签/源码导出对齐、作者R-Drop原始损失、随机采样+Dropout的中断恢复、P-C为0仍保存第一个checkpoint且同分保留更早Epoch；记录见official-tests.log和losver-tests.log。
真实GPU smoke分别记录在smoke/primevul_paired/<method>/smoke.json，均为Train诊断，不是正式性能。
SVulD的同函数双Dropout及对称KL求和按公开代码执行；contrast字段仅在Train保留真实配对，正式R-Drop分支不使用该字段，Valid/Test将其设为函数自身。未补入额外InfoNCE或跨版本损失。
